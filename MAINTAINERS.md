## What maintainers do

- **Review pull requests.** Both are listed in [`.github/CODEOWNERS`](.github/CODEOWNERS), so
  either can approve. Changes to CI/CD, the build system, the guard scripts or the security
  policy always require a maintainer's approval.
- **Handle security reports.** Vulnerabilities are reported privately — see
  [`SECURITY.md`](SECURITY.md). Never in a public issue.
- **Cut releases.** Merging a pull request publishes nothing; a maintainer decides when a
  release happens and pushes a protected version tag. See [`CONTRIBUTING.md`](CONTRIBUTING.md).
- **Triage issues** and keep dependencies current.

## Contacting a maintainer

| Reason | Where |
| --- | --- |
| Bug or feature request | [Issues](https://github.com/xorcise-ai/xorcise/issues) — use the templates |
| Usage question | [Discussions](https://github.com/xorcise-ai/xorcise/discussions) |
| **Security vulnerability** | **Private advisory** — see [`SECURITY.md`](SECURITY.md) |
| Code of Conduct concern | guru@xorcise.ai |

Please use the public channels for anything that is not sensitive — an answer in the open helps
the next person with the same question.

## Becoming a maintainer

Maintainership is offered, not applied for, and follows a track record of good contributions
and sound judgement — particularly around security, since maintainers can approve changes to
the release pipeline.

If you would like to move in that direction, the path is ordinary: pick up issues, review other
people's pull requests, and help with triage. See [`CONTRIBUTING.md`](CONTRIBUTING.md).
